## Build & Validation

- **Always run** `nix flake check --no-build` **before declaring changes done** — catches eval errors without building.
- **Run** `nix flake check` **(with build) before pushing to main** — ensures all systems build.
- **Stage new files with `git add` before any nix eval** — flakes only see tracked files.
- **Use `--override-input` for local iteration** on `nix-ai-tooling` or `private-config`:
  ```bash
  nix flake check --override-input ai-tooling path:../nix-ai-tooling
  ```

## Module Hygiene — Prefer Modules Over Ad-Hoc Functions

**Core rule: If configuration exceeds a few lines, it belongs in a module file, not an inline function.**

- **Follow the 5-layer NixOS hierarchy** (global → hardware → optional → host → HM). Never bypass layers.
- **Follow the 5-layer HM hierarchy** (machine → global → CLI → custom → desktop). Import order matters.
- **Optional modules live in `hosts/common/optional/`** — every service is opt-in via host `default.nix`.
- **Use `mkEnableOption` for all new modules** — explicit enable, type-checked, discoverable via `nix eval`.
- **Define module options in `options` section, implementation in `config`** — separate declaration from wiring.
- **No inline `config = { ... }` blocks in host files** — delegate to modules in `hosts/common/optional/` or `features/`.
- **No anonymous functions generating config** — e.g., avoid:
  ```nix
  # ❌ Bad: ad-hoc function in host/default.nix
  config = let makeService = name: { ... }; in makeService "foo";
  ```
  Instead:
  ```nix
  # ✅ Good: proper module in hosts/common/optional/foo.nix
  { config, lib, ... }: {
    options.services.foo = { enable = lib.mkEnableOption "foo service"; };
    config = lib.mkIf config.services.foo.enable { ... };
  }
  ```
- **Custom HM modules go in `modules/home-manager/`** with a clear purpose comment.
- **One module = one concern** — split if a module configures unrelated services.

## Impermanence Discipline (cobalto, rubi)

- **`/persist` is the only state surviving reboot** — audit before adding persistence.
- **Define persistence per-host** in `hosts/{cobalto,rubi}/impermanence.nix` — no shared templates.
- **Secrets decrypt to `/run/secrets/` then bind-mount into `/persist`** via sops-nix + impermanence.
- **Before adding a service that writes state**: add its paths to impermanence config first.
- **If a service fails at activation, check `/persist` for missing paths** — deploy-rs rolls back on ANY failed unit.

## Three-Repo Contract

- **nix-config (public)** never references customer names — only neutral exports:
  `workMcpConfig`, `workExtras`, `nixosModules.work`, `secretFiles`, `opencodeConfig`.
- **nix-ai-tooling (public)** — reusable HM AI modules only. No machine-specific config.
- **nix-private-config (private, git+ssh)** — customer configs, secrets, private MCP packages.
- **Runtime secret names are neutral**: `WORK_JIRA_A_*`, `/run/secrets/work-jira-a-*`.
- **Private repo pinned by branch ref** (`?ref=employer-cleanup`) in `flake.nix`.

## Secrets (SOPS)

- **Static age key at `/nix/persist/var/lib/sops-nix/key.txt`** — survives impermanence.
- **Per-host encrypted files**: `hosts/<host>/secrets.yaml` + `.sops.yaml`.
- **Two tiers**: system (nix-config) + work/personal (private-config via `secretFiles` export).
- **Never commit unencrypted secrets** — SOPS only.

## Deployment

| Machine | Method | Command |
|---------|--------|---------|
| rubi | local | `sudo nixos-rebuild switch --flake .#rubi` |
| lapislazuli | local | `darwin-rebuild switch --flake .#lapislazuli` |
| lonsdaleita | local | `nix-on-droid switch` |
| cobalto | deploy-rs (local build) | `nix deploy .#cobalto -- --impure` |
| granate | deploy-rs (remote build) | `nix deploy .#granate -- --impure` |

- **Before re-deploy after failure**: `systemctl reset-failed <unit>` on target, then deploy again.
- **`deploy-rs` arg must be flake ref**: `nix run .#deploy -- .#cobalto` (not `-- cobalto`).

## Lean / Cleanup Rules

- **Remove unused imports** — dead code in `optional/` or `features/` = confusion.
- **Audit `hosts/common/optional/` quarterly** — if no host imports it, delete or document why it stays.
- **Audit `features/` modules** — per-platform overrides in `home/diego/{machine}.nix`, not conditionals in shared modules.
- **Custom packages in `pkgs/` must have a consumer** — if no host/HM uses it, remove it.
- **Overlays in `overlays/` must document why they exist** — upstream fix preferred.

## AI Tooling Workflow (nix-ai-tooling → nix-config)

1. Write module in `nix-ai-tooling/modules/<name>.nix`, export in its `flake.nix`.
2. **Register in TWO places in nix-config**:
   - `flake.nix`: `inherit (inputs.ai-tooling.homeManagerModules) <name>;`
   - `hosts/rubi/default.nix`: `inputs.ai-tooling.homeManagerModules.<name>` in `home-manager.users.diego.imports`
3. Enable/configure in `home/diego/features/ai/<file>.nix`.
4. `nix flake update ai-tooling`, commit lock + wiring, rebuild.
